# TaskForge AI

**TaskForge AI** — работающий MVP платформы для подготовки и открытого выбора бизнес-задач студенческими командами. Представитель бизнеса вводит черновик, получает уточняющие вопросы, проверяет сформированную карточку и публикует её с прозрачным рейтингом готовности. Команды самостоятельно выбирают задачи и отправляют предложения, а бизнес вручную принимает или отклоняет каждый отклик.

Проект создан командой **БАТЫС** для практического хакатона AI Sana.

## Что реализовано

- свободный ввод черновика бизнес-задачи;
- AI-анализ описания и семь уточняющих вопросов;
- безопасный локальный режим при отсутствии или ошибке внешнего API;
- формирование редактируемой карточки без добавления неподтверждённых фактов;
- обязательная ручная проверка карточки перед публикацией;
- прозрачный рейтинг готовности от 0 до 100 с разбивкой по критериям;
- подсказки о недостающих сведениях и пересчёт после каждого изменения;
- открытый каталог со всеми задачами, сортировкой по рейтингу и фильтрами;
- пять синтетических задач разной степени готовности;
- пять профилей команд и пять демонстрационных откликов;
- отправка неограниченного числа предложений с идеей, планом, сроком и ссылкой;
- ручной выбор, отклонение или возврат предложения на рассмотрение;
- сохранение изменений в локальном хранилище браузера;
- WebMCP-инструменты для чтения каталога, запуска черновика и отправки отклика.

## Основной пользовательский сценарий

1. Представитель бизнеса вводит слабое исходное описание.
2. Система проверяет ввод и задаёт семь вопросов о пользователях, данных, результате, критериях успеха, ограничениях и связи с бизнесом.
3. Ответы переносятся в редактируемую карточку. Система не придумывает факты.
4. Пользователь дополняет карточку и видит рост предварительного рейтинга.
5. После ручной проверки карточка подтверждается и публикуется.
6. В каталоге задача занимает позицию согласно рейтингу, но остаётся доступной при любом балле.
7. Студенческая команда самостоятельно выбирает задачу и отправляет предложение.
8. Представитель бизнеса вручную выбирает одну, несколько или ни одной команды.

## Формула рейтинга

Баллы начисляются за заполненные поля подтверждённой карточки.

| Критерий | Вес | Условие |
|---|---:|---|
| Контекст и потребность | 20 | Заполнены текущая ситуация и необходимое изменение |
| Данные и материалы | 20 | Указаны доступные данные, примеры или источники |
| Ожидаемый результат | 15 | Описан конкретный результат работы команды |
| Критерии успеха | 15 | Есть измеримые признаки успешного решения |
| Ограничения | 10 | Указаны сроки, технологии, доступы или границы |
| Пользователи | 10 | Понятно, для кого создаётся решение |
| Связь с бизнесом | 10 | Есть контакт и формат обратной связи |

Уровни готовности:

- **0–39** — черновик;
- **40–69** — рабочая;
- **70–89** — готовая;
- **90–100** — приоритетная.

Низкий рейтинг не скрывает карточку и не запрещает отклик.

## AI-функция

При наличии `OPENAI_API_KEY` сервер отправляет черновик в OpenAI Responses API и запрашивает структурированный JSON по строгой схеме. Ответ проходит проверку количества вопросов, допустимых ключей и типов данных. Ключ используется только на сервере и не передаётся в браузер.

Если ключ отсутствует, превышено время ожидания или ответ не прошёл проверку, приложение автоматически использует локальный набор контекстных вопросов с тем же форматом. Пользователь видит активный режим в интерфейсе.

Полный промпт, формат входа и выхода описаны в [документе AI-контракта](docs/AI_CONTRACT.md).

## Технологии

- HTML5, CSS3 и JavaScript без тяжёлого клиентского фреймворка;
- Node.js и встроенный HTTP-сервер;
- OpenAI Responses API и Structured Outputs;
- `localStorage` для демонстрационного хранения данных;
- WebMCP для структурированного управления основными действиями страницы;
- OpenAI Sites для приватной демонстрационной версии.

## Архитектура

```text
Браузер
  ├─ Конструктор задачи ──► рейтинг ──► каталог
  ├─ Форма отклика ───────► список предложений ──► ручное решение бизнеса
  └─ localStorage          хранит задачи, отклики и статусы демо
            │
            └─ POST /api/analyze
                    │
                    ├─ OpenAI Responses API, если ключ настроен
                    └─ локальный резервный анализ при любой ошибке
```

В опубликованной статической демоверсии используется локальный AI-режим. Серверный режим с OpenAI доступен при локальном запуске с ключом.

## Установка и запуск

Требуется Node.js 18 или новее. Сторонние пакеты устанавливать не нужно.

```bash
git clone https://github.com/BAITC-Hacks/hack-032ef148-team.git
cd hack-032ef148-team
npm start
```

Откройте в браузере: [http://127.0.0.1:4173](http://127.0.0.1:4173).

Для запуска с OpenAI:

1. Скопируйте `.env.example` в `.env`.
2. Вставьте реальный ключ в `OPENAI_API_KEY` только в локальном `.env`.
3. Запустите `npm start`.

Файл `.env` исключён из Git. Не публикуйте API-ключи и не вставляйте их в клиентский JavaScript.

## Как проверить решение

### Сценарий для жюри

1. На вкладке **Конструктор** нажать «Заполнить демо-пример».
2. Нажать «Проанализировать с AI» и получить семь уточняющих вопросов.
3. Ответить минимум на три вопроса и сформировать карточку.
4. Дополнить поля и нажать «Пересчитать рейтинг» — балл и рекомендации обновятся.
5. Подтвердить ручную проверку и опубликовать задачу.
6. Убедиться, что она появилась в каталоге на позиции согласно рейтингу.
7. Нажать «Откликнуться», заполнить идею, план, срок и ссылку.
8. В блоке решений вручную выбрать или отклонить команду.

Проверка синтаксиса:

```bash
npm run check
```

## Данные и интеграции

В `dist/app.js` находятся синтетические данные:

- пять карточек задач;
- пять профилей студенческих команд;
- пять предложений со статусами рассмотрения.

Внешняя интеграция — OpenAI Responses API. Персональные и чувствительные признаки не передаются и не используются при оценке. Решение о выборе команды никогда не принимает AI.

## Известные ограничения

- нет регистрации, ролей и синхронизации между устройствами;
- данные демо хранятся только в текущем браузере;
- нет чата, уведомлений, календаря и файлового хранилища;
- опубликованная статическая версия использует локальный AI-режим;
- локальный резервный режим формирует проверенный набор вопросов, а не обращается к языковой модели;
- ссылки на прототипы в синтетических данных являются демонстрационными;
- начисление баллов выбранной команде после фактического этапа показано только статусом решения бизнеса.
